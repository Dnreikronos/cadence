# Unwrap with reveal-risk warning (#56)

Implement R6/R6b together on current main, reusing Supabase authentication,
wallet association, audited Vault reads and unsigned transaction compilation.
The existing checkout contains unrelated wrap work; use the attached
`unwrap-reveal-risk` worktree and `proof_unwrap_reveal_risk` branch.

## Contract

- `POST /unwrap` accepts `wallet`, integer base-unit `amount`, `aes_key`,
  `acknowledge_reveal_risk`, and an optional first-use `wallet_signature`.
  The balance key has the same transient encoding as `/transfer`.
- Derive both token accounts from the verified wallet and deployed devnet mint.
  Authorize the wallet before reading its key or payment history.
- Read confirmed incoming standalone transfers and finalized run payments.
  Decrypt their recipient ciphertexts only after an audited Vault read. Never
  persist a received amount or accept caller-supplied payment history.
- Return `reveal_risk: {level: none|near|exact, matches: [{payment_id, paid_at}]}`.
  An exact match takes precedence. Near means an inclusive percentage difference
  relative to the received amount, using integer arithmetic. Default 100 basis
  points (1%); `PROOF_REVEAL_RISK_TOLERANCE_BPS` accepts 0..=10000.
- Risky requests without acknowledgement return 409 with a fixed error code
  and the structured risk; no withdrawal proofs or transaction are built.
  `POST /unwrap/check` exposes the same check without requiring an AES key.
- Build one unsigned v1 transaction: create the normal USDC ATA idempotently,
  withdraw confidential available balance using upstream proof helpers, then
  burn wrapped tokens and transfer escrow USDC to that ATA. The wallet is the
  only signer. Pending credits must already be applied (#68).
- Store only public withdrawal transaction bytes and user-bound receipt metadata.
  `POST /unwrap/confirm` verifies successful finalized execution, the exact
  prepared message and its wallet signature before immutable persistence.
- History, authentication, key, or proof failures fail closed with fixed errors.
  Bound work using the existing shared CPU semaphore and HTTP limits. Reject
  history exceeding 1000 payments rather than silently omitting warnings.

## Verification

Targeted tests cover exact/near/safe amounts, inclusive tolerance boundaries,
overflow, ciphertext decoding, real withdrawal proofs, wallet/account mismatch,
insufficient balance, missing acknowledgement, failed audited reads, receipt
ownership and immutable confirmation. Use a fresh disposable Vault database,
not an existing application database. Run fmt, compiler and clippy checks.

Live acceptance additionally needs a devnet withdrawal and normal-USDC balance
verification. Record separately whether a wallet/provider browser flow was
actually exercised; automated tests alone do not establish Phantom acceptance.

## Results

Implemented the prepare/check/confirm endpoints, audited ciphertext history,
configurable risk tolerance, atomic withdrawal builder and immutable receipts.
The migration also preserves the payment-attempt snapshot column layout so
adding receipt metadata cannot break payroll retries.

`cargo fmt --check`, `cargo check --locked --all-targets`, and
`cargo clippy --locked --all-targets -- -D warnings` passed. The vendored token
client retains its pre-existing deprecation warning. Fourteen targeted tests
passed, including the real Vault/receipt roundtrip and run retry after migration;
the complete repository test suite was not run. CI now runs the unwrap database
test in a separate disposable Vault instance.

The [live devnet evidence](../dev/spikes/2026-10-04-unwrap-devnet.json) confirms
the exact-warning gate, externally signed 1918-byte transaction, confidential
debit, ordinary-USDC credit, immutable HTTP receipt and independent RPC result.
This used a disposable SDK wallet and local Auth fixture. Phantom UI acceptance
and live frontend request wiring remain unverified; the live backend needs the
AES balance key and wallet association fields described in
[UNWRAP_API.md](../dev/UNWRAP_API.md).
