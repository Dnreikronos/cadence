# Authenticated transfer API

Issue: https://github.com/Dnreikronos/cadence/issues/54.

## Contract

Expose `POST /transfer` and `POST /transfer/confirm` over the merged #53
builder. The user chose Supabase login and a user-to-wallet association.
Validate every bearer token with this project's Supabase Auth `/auth/v1/user`;
never trust decoded JWT claims or a caller-supplied audit actor.

Preparation accepts `company_wallet`, `sender`, `recipient` (Token-2022 account
addresses), `amount` (decimal base-unit string), and `aes_key` (base64 16-byte
balance key). The mint is the deployed wrapped-USDC mint, read from fresh RPC
state. No arbitrary mint or client-supplied account snapshot is accepted.
For an unlinked wallet, also require `wallet_signature`: an Ed25519 signature
of UTF-8 `Cadence wallet association\nuser:<verified-user-id>\nwallet:<company-wallet>`.
Persist an immutable, unique wallet/user association only after verifying it.
Subsequent requests use that association and fresh sender ownership checks.
The wallet signs the returned transaction outside the proof service.

Load the viewing key through the durable audited accessor, attributed to the
verified Supabase user. Generate proofs off the async executor. Read real rent
quotes and a fresh blockhash. Return base64 unsigned v1 bytes, request ID,
required signers, source/destination/mint and blockhash expiry. Keep the amount,
AES key, bearer token and wallet association signature transient; never put
them in a receipt, audit reason, error or log.

Confirmation accepts `request_id` and transaction `signature`, authenticates
the same user and reads a finalized devnet transaction. Check successful
metadata, exact prepared message, sole expected signer, and cryptographic
signature before persisting an immutable receipt. Idempotent retries survive
RPC outages; another user's requests return 404. Concurrent confirmations
cannot overwrite each other. Never submit or sign from the backend.

Use separate least-privilege database roles for transfer receipts and Vault.
Require certificate/hostname-verified TLS outside explicit loopback test
connections, connect/query timeouts and per-request autocommit key connections.
Bound request bodies, peer/wallet rate and concurrent expensive builds. Keep
missing configuration fail-closed with fixed JSON errors.

## Verification

Run formatting, compiler, Clippy, targeted HTTP/auth/storage/proof regression
tests and migrations against disposable hosted-equivalent Vault/Postgres.
Cover token rejection, wallet binding and theft attempts, cross-user access,
no sensitive error echo, wrong cluster, missing accounts, failed proof/audit
storage, exact-message confirmation, forged signatures, races and retries.
Test browser/provider signing and devnet confirmation when a compatible
user-controlled test wallet and enrolled keys are available; report that
acceptance separately from mocked RPC and local signing.

## Implemented evidence

Formatting, `cargo check --locked --all-targets` and Clippy with warnings denied
passed. The existing vendored token client emits a dependency deprecation
warning. Targeted auth, transfer HTTP, wrap HTTP/limits/storage, confidential
proof and compatibility suites passed: 21 tests; three database tests were
intentionally ignored in that run. The separate ignored transfer HTTP test
passed against real disposable Supabase Postgres and Vault, covering durable
audit/receipt storage and role isolation. No full local suite or remote CI run
is claimed.

The actual transfer API also passed a live browser-driven Turnkey test-adapter
flow with real Supabase Auth and Vault. The [devnet transfer](https://explorer.solana.com/tx/2UMi2A8NM8VQR1XA47aE716CoggjMTchyzJg6VthQxRAECCRtpUTw5q8pQdidz9pn4iLAJEmkXNER7MRRWhpRQyh?cluster=devnet)
finalized at slot 507081114: 2,913 wire bytes, ten instructions, three closed
proof contexts, verified sender debit and recipient credit, and ciphertext
observed by an independent RPC. Existing root test credentials stayed in the
local adapter, separate from the proof service. This checks provider
compatibility; user-controlled production browser onboarding remains #77.
